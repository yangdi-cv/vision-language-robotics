# 一个可执行的小功能

目标：固定桌面场景中，根据指定目标执行单件操作。先证明同初态不同指令能产生正确选择和动作，再谈新布局，不同时扩展Qwen、导航和更多模型。

顺序：
1. 核验训练与部署一致性。已发现旧LoRA注意力输出合并语义错误，先用实际上游算子验证，再比较已有权重的未合并运行和修正合并输出。没有适配器的官方基座不受影响。不同进程的BF16计算可有约0.002动作差，保留历史输出，不把跨进程逐位相等当成必要条件。
2. 优先复测已有权重，所有结果另存；不覆盖旧分数。部署优先用原生未合并LoRA，避免把合并误差混入训练能力判断。
3. 若已有权重仍不足，选一对已验收的同场景双目标轨迹做最小学习验证。先看训练观察上的实际生成动作，而不只看流匹配损失；训练场景能完成后，才加新位置。
4. 功能验收分开记录：选择目标、抬起、稳定放置、另一件是否被扰动。训练场景通过不能写成泛化成功。仅仿真，不连接硬件。

所有大模型单进程、独立systemd用户服务，软14GiB/硬16GiB，保留分块加载，不改系统Swap、驱动或已有环境。原报告追加更正说明，原始源码和数据不覆盖。没有启动新训练。
