# 私有GitHub仓库的代码布置建议

建议章节作为阅读入口，共享功能只维护一份实现。把所有实现直接复制到24个章节目录，会使同一个模型加载、图像处理或控制函数出现多份，后续难以保证一致。

```text
embodied-operation/
├── README.md
├── docs/
│   ├── report/                # 中文LaTeX；后续加入英文入口
│   └── code_index/            # 按报告章节、阶段编号阅读代码
├── src/
│   ├── observation/           # 相机、图像方向、帧传输
│   ├── perception/            # Qwen、目标检测、可供性与完成判断
│   ├── task_management/       # 任务准入、阶段状态和停止条件
│   ├── execution/             # 策略调用、动作接口、控制桥
│   ├── simulation/            # 场景、机器人、传感器
│   └── deployment/            # 板端加载、服务和资源记录
├── experiments/
│   ├── ch02_platform/s01_so101/
│   ├── ch02_platform/s02_observation/
│   ├── ch03_autonomy/...
│   ├── ch04_hierarchy/...
│   ├── ch05_mobile/...
│   ├── ch06_affordance/...
│   └── ch07_edge/...
├── configs/                   # 运行与实验配置
├── tests/                     # 接口与数据协议检查
├── scripts/                   # 统一运行和整理工具
├── third_party/README.md      # 上游项目、版本、许可证与获取方式
└── artifacts/README.md        # 权重、数据、完整结果的外部位置与校验值
```

## 每个实验小节保存什么

每个sXX目录保留README、配置、运行入口和必要的小型测试输入；训练、推理、规划等通用函数从src导入。README写清对应报告小节、解决的问题、运行命令、结果文件格式和依赖。成功率不是代码常量，应从实际结果汇总。

图像示例可以放在报告目录。视频单独放videos，较大时采用Git LFS或独立归档；报告引用的相对路径保持一致。不要把全部模型、原始视频、虚拟环境、训练缓存放进普通Git历史。

## 本轮实际做了什么

目前仅建立code_index/ch02到ch07下的24份阶段索引，并生成现有源码清单，不移动或重写原项目实现。这样原报告的运行路径与结果不会因整理文档而失效。后续真正迁移时，先整理共享接口，再逐个替换章节入口，并保留旧版本对应关系。

厂家工程和上游库保留来源与版本，自己编写的部分单独整理。配置中的机器路径与认证信息应从环境或本地配置读取。仓库是否公开由你手动管理，本轮没有上传或修改GitHub。
