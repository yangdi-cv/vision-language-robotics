# 腕部相机场景理解

本地 Qwen3-VL-4B-Instruct 连续观察模块，统一窗口提供实时预览、主从臂操作启停、结构化分析与实验留档。Qwen 推理进程没有机械臂运动接口；窗口仅启动或停止人工主从遥操作进程。

## 启动

先关闭旧 Qwen 窗口、独立相机预览、独立遥操作和示教采集，再运行：

```bash
/home/yd/Documents/VLA/perception/qwen_scene/start
```

启动自动加载模型并连续推理：上一轮完成后立即读取最新相机帧，丢弃中间未分析的帧，不积压请求。推理期间保留上一轮回答供阅读，同时继续实时预览。窗口显示上次回答对应多少秒前的画面及推理耗时。

模型加载完成且相机正常后，“启动主从操作”可用。点击并确认底座固定、活动空间和断电方式后启动；缓慢移动黑色主臂，白色从臂跟随。控制沿用 10 Hz、5 单位限幅、肩 P=28、肘 P=24，启动前强制核对校准。模型输出只显示，不发送动作。

正常停止：先托稳白色臂，再点击“停止主从操作”。窗口发送中断，由控制进程恢复参数、关闭扭矩；控制 CSV 与日志保存。关闭窗口时若双臂运行，会先要求停止双臂，再关闭窗口。异常运动直接断开 12V 电源；终端 Ctrl+C 是立即中断路径，会关闭扭矩，需防止机械臂落下。

分析已有图像（图像原样输入，不再次旋转）：

```bash
/home/yd/Documents/VLA/perception/qwen_scene/start --image /绝对路径/图片.png
```

## 输出与限制

连续窗口每次启动创建 `records/scene_understanding/live_时间戳/`，相机线程只发布一张最新帧，预览和推理共用同一来源。Qwen 与主从控制分别运行在独立进程，不等待对方推理。相机发布/预览目标约 10 Hz，真实主从周期需在联动运行后实测。

每次分析在本次会话 `analyses/scene_时间戳/` 保存（静态图片模式仍直接使用 `scene_时间戳`）：

- `input.png`：实际分析图像。
- `prompt.txt`：提示词。
- `result.json`：模型版本、输入大小、来源、旋转配置、加载及推理耗时、原始回答、结构化结果和校验状态；连续模式增加 frame_id、主机图像接收/取帧/完成时间及输入年龄。

连续窗口还保存 `qwen.log`、控制日志、最新结果与进程状态。相机接收时间不是硬件曝光时间。相机无新鲜帧超过一秒时暂停提交新推理，避免反复处理旧画面。

结构化字段：场景描述、可见物体、目标可见性、夹爪开闭、目标相对位置、接触证据及不确定性。无效 JSON 保留原回答并标为校验失败，不作为有效结果。

这是观察原型，不是目标检测精度评测、3D 抓取定位、闭环动作策略或 VLA。模型可能误认物体或空间关系。单帧不能证明抓取牢固或任务成功；显式允许 unknown/null，不根据任务文本强行假定目标存在。结构合法不代表事实正确。

## 与示教采集的关系

`SO101/code/scripts/ubuntu/start-record` 已默认显示采集图像，不需要另开预览。关闭采集窗口会停止并关闭从臂扭矩，需先托稳；终端 Ctrl+C 也可停止。

## 验证

## 目标检测与单目深度可视化

窗口采用三栏：左侧实时 RGB，中间纯深度彩色图 + 检测框，右侧 Qwen 文字持续更新。Ultralytics 独立进程在同一帧上运行 YOLO26n 检测和 YOLO26n-depth，处理完成就取最新帧，最大提交约 10 Hz。框和深度图显示其实际分析帧，不把旧框叠在新画面上；显示画面年龄。

- Ultralytics 8.4.175，权重在 `models/ultralytics/`，来源及 SHA-256 在 `manifest.json`。
- 检测使用通用预训练类别，置信度阈值 0.35，输入 640；深度输入 768。蓝色塑胶壳不是专门训练目标，可能漏检；腕部夹爪也可能被误认成其他类别。
- 深度图暖色近、冷色远，固定线性 0–3 m 色阶；下方图例标记 0、0.75、1.5、2.25、≥3 m，超出范围的颜色饱和，同一米制估计对应相同颜色。无效深度显示黑色。
- 模型输出为米制估计，但此相机/场景尚未标定或用真值验证，不能直接作为真机抓取距离。框上仅显示 `Depth X.XX m`，不显示类别或置信度；该值是整个矩形区域有效深度的中位数，可能混入背景，不是目标中心的真实距离。
- Qwen 继续输入原始旋转图像，没有把检测框或深度图当作额外输入。此阶段只是可视化集成，不是感知融合策略。
- 会话保存 `latest_vision.npz`（同帧检测图、深度彩色图、原始深度及元信息）、`vision_timing.csv`、`vision.log` 与状态；只保留最新密集图，避免连续生成大量图片。
- 官方接口说明：https://docs.ultralytics.com/tasks/depth

三张真实示教图测试深度输出与 RGB 对齐且数值有限。暖机后检测＋深度约 14–15 ms；与 Qwen 并行时末尾五次约 15–35 ms。窗口自检完成 30 次检测/深度和 3 次 Qwen，未启动机械臂。这些是当前配置时延，不是检测或深度精度指标。第 0 帧夹爪被错认为 toilet、第 305 帧被错认为 airplane，第 152 帧无检测框，需后续适配/标注评测。

`--self-test` 自动启动真实相机与模型，连续完成三次分析后退出，禁用机械臂启动按钮。已验证输入帧序号 38→63→84，取帧年龄约 48–113 ms，推理约 2.03–2.38 秒，无请求堆积。模拟总线生命周期测试覆盖校准不一致拒绝写指令、中断后恢复 P 参数并关闭扭矩。以上不等同于已测得三者真机联动性能。


### 输入方向与推理记录（2026-11-13修订）

`SceneEngine.analyze` 默认不旋转，`rotation` 表示从传入的原始像素顺时针旋转的角度。实时相机生产端已旋转，`continuous_worker` 明确传入 `pixels_already_rotated=True`。保存的 `input.png` 与模型使用像素一致；不要再根据JSON的总旋转角重复转图。

相机观察与LIBERO规划/检查共用`SceneEngine.generate`；每次生成返回完整prompt及其哈希、模型固定revision、库版本、生成参数、图像尺寸与像素哈希。LIBERO worker的请求和响应写入`logs/*.requests.jsonl`，不是只在最终事件摘要中记录。V2分类评分另记实际评分prompt、LoRA文件哈希和阈值。旧结果不自动补录缺失的配置。
