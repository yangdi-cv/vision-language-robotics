# 视觉语言机器人项目：工程改进阶段报告

日期：2026年11月22日

## 摘要

本轮按照代码评审意见，重点改进当前同场景仿真和 Jetson 视觉联调的工程实现。保留已有实验和数据，将分散的配置、进程通信、运行记录、接口校验和文件校验整理为公共运行层，并接入实际运行入口。预接触与完整操作原来分别维护流程，现在共用同一个调度函数。

验证范围包括原有92项离线测试和35项新增测试，共127项；另对维护范围运行代码检查、格式检查和严格类型检查。新增测试覆盖模型输出异常、进程超时与退出、坐标转换、正运动学、碰撞白名单、轨迹结构、里程碑确认，以及模拟器启动失败后的日志与退出码。历史数据、报告和视频等494个已跟踪文件与改进前版本逐一比对，内容未改变。

本轮没有重训模型，也没有新增成功率。GPU推理、完整ROS2仿真和Jetson实测需要在完整环境中用新标签回归；CPU检查只验证相应接口和故障处理。

## 一、问题与改进范围

评审指出的核心问题是：早期研究代码能够在原机器上运行，但搬迁、定位错误和持续维护的成本较高。主要原因包括路径与设备信息散落、流程重复、跨模块数据缺乏约束，以及异常和运行记录不完整。

本轮从当前交付链路入手，维护范围由 `repository/MAINTAINED_ENTRYPOINTS.json` 明确列出。旧实验的模型、提示词、数据划分和历史结论保留，不通过重写旧结果来表现改善。

| 评审问题 | 本轮处理 | 范围说明 |
|---|---|---|
| 路径、解释器、设备地址写死 | JSON配置与环境变量覆盖；增加只读诊断入口 | 当前调度、ROS启动、运动学描述和Jetson服务入口 |
| 密码登录与管理权限混入推理流程 | 新入口使用SSH密钥和主机密钥检查；移除自动sudo与swap修改 | 新包排除11个含密码登录逻辑的历史远程驱动 |
| 模块复制、流程漂移 | 公共运行层；预接触和完整操作共用调度 | 历史制图、训练与一次性部署脚本未全量迁移 |
| 裸字典与类型缺失 | 核心状态使用数据类；跨边界数据作运行期校验 | 公共运行层严格类型检查，不冒充全仓严格类型覆盖 |
| 异常信息与落盘不足 | 完整堆栈、分级日志、阶段记录、原子快照、非零失败返回 | 新回合生效，旧结果不重写 |
| 风险链路缺测试 | 增加协议、几何、轨迹、状态机与入口失败测试 | 尚不替代ROS消息真实回放或实体设备测试 |
| 依赖与元数据分散 | 保留环境分工，固定CPU开发工具依赖，记录参数和代码版本 | 不把互不兼容的CUDA/JAX/ROS环境合成一个环境 |

相关代码在 `vla_runtime/`、`configs/runtime.example.json` 和 `scripts/check_engineering.py`。

## 二、配置和环境迁移

### 2.1 配置入口

配置集中到 `configs/runtime.example.json`，分为路径、远程设备和阈值三个部分。解释器、ROS安装前缀、远端部署目录和端口均可配置。相对路径以工程根目录为基准，不依赖执行命令时的当前目录。

本机配置由 `VLA_CONFIG` 指定，工程根目录由 `VLA_ROOT` 指定。解释器和设备参数也可用明确的环境变量覆盖。未知字段直接报错，避免配置拼错后仍静默使用默认值。

诊断命令 `vla-doctor` 只检查本机路径，不加载模型、不联网、不连接机械臂。模型环境、策略环境和ROS环境继续分开，不修改系统Python。

### 2.2 ROS与策略子进程

迁移时检查了启动器对环境变量的处理。原ROS启动器会清空PYTHONPATH，若只在上层引入公共包，ROS子进程将无法导入。现在先清理外来模型环境，再恢复ROS自身路径和当前工程的运行层路径。

针对这一点新增启动器测试：使用临时ROS设置文件，确认公共包可导入，原模型环境路径被隔离，ROS包路径保留。该测试不要求安装ROS。

策略共驻显存启动器也补入工程根目录。原显存配置和模型进程隔离方式不变。

相关代码在 `experiments/mobile_vla/scripts/ros-python`、`experiments/vla_libero/scripts/python_shared` 和 `tests/runtime/test_entrypoints.py`。

## 三、公共接口与调度收敛

### 3.1 通信与子进程

Unix socket和模型逐行JSON协议共用同一个通信模块。读取设置总期限，限制单条消息大小，拒绝非对象JSON和非有限数字。模型标准输出继续只承载JSON协议；普通日志写标准错误，避免日志破坏调用方解析。

超时或协议错误会清理工作进程。只有当子进程拥有独立进程组时才向进程组发信号，否则只终止该子进程，避免误伤调用者所在进程组。

旧的 `rpc.py` 和 `worker_client.py` 保留为兼容导出，避免调用者继续维护另一套实现。

相关代码在 `vla_runtime/transport.py`。

### 3.2 同一调度入口

`run_cases.py` 通过 `--task precontact` 或 `--task combined` 选择任务。`run_combined.py` 转为兼容入口，调用同一函数。导航、定位、MoveIt执行、失败处理和结果保存不再各写一份。

完整操作仍遵循先预接触、停止MoveIt及其控制桥，再交还策略控制权的原流程。视觉里程碑检查与官方任务成功判定的角色不变，未把仿真真值改成控制决策。

新标签禁止覆盖；前缀、模式、初态和修正次数作基本检查。模拟器退出或规划子进程失败会给出非零退出码，避免外层脚本把失败当作正常完成。

相关代码在 `experiments/mobile_qwen/closed_loop_20261115/scripts/run_cases.py`。

### 3.3 运行期数据约束

类型标注用于开发期检查；运行期仍显式检查模型和进程返回的数据。主要约束如下。

| 数据 | 检查内容 |
|---|---|
| 模型定位 | 成功字段必须为布尔真；二维坐标为有限数字，处于0到1000的归一化范围 |
| 机械臂状态 | 7个关节、2个夹爪位置、3维末端坐标，拒绝NaN和无穷大 |
| 旋转 | 3×3矩阵，满足正交性与行列式为正一 |
| 碰撞几何 | 尺寸为正，网格三角形索引有效，位置与旋转合法 |
| 目标姿态 | 位置有限，四元数长度归一 |
| 轨迹 | 关节名不重复、点数非零、位置维度一致、时间严格递增 |
| 里程碑 | 仅接受布尔完成状态，字符串“false”不能被当作完成 |

相关代码在 `vla_runtime/schemas.py`、`geometry.py` 和 `milestones.py`。

## 四、规划与仿真执行检查

MoveIt规划前检查状态与场景数据，验证碰撞白名单引用的链接确实存在。未列入白名单的接触默认禁止，生成的碰撞矩阵保持对称。

正运动学响应先检查错误码和位姿数量，再比较MoveIt末端与仿真末端。两者不一致时保留具体误差，阻止继续执行。原有误差阈值保持为0.00001米。

执行成功需同时满足MoveIt错误码成功、动作状态成功，并存在实际执行轨迹。不能仅靠一个成功码判断。仿真控制桥也检查轨迹结构和反馈数值，仍使用MuJoCo测量状态作为反馈，不把目标关节位置直接作为实际位置。

控制桥逐步记录实际反馈，执行结束另外保存完整轨迹与错误信息。异常情况下锁会释放，避免因为落盘失败导致后续请求永久忙碌。

这些修改提高的是输入约束和失败诊断质量。本轮没有运行完整ROS2物理闭环，不能据此宣称碰撞行为或任务成功率已经通过重新验证。

相关代码在 `plan_execute.py`、`physics_bridge.py`、`kinematics.py` 和 `moveit.launch.py`。

## 五、日志、元数据和远程服务

### 5.1 中途失败也有记录

每个新回合启动时就建立阶段日志和元数据。模拟器尚未创建结果目录便退出时，仍可在日志目录找到错误、进程退出码和已完成阶段。

阶段日志使用JSON逐行写入，每条记录带序号和UTC时间，并同步到文件。快照先写入同目录临时文件，再原子替换。完整异常堆栈包含异常链，减少只看到简短错误而无法定位的问题。

记录分工如下：

- `run_metadata.json`：代码版本、工作区状态、运行参数、配置和参数摘要。
- `progress.jsonl`：启动、定位、尝试结果、里程碑检查、失败与结束事件。
- `case_snapshot.json`：最近一次回合状态。
- 控制器逐步记录与最终JSON：轨迹、实际反馈、错误及堆栈。
- 模型响应沿用原推理元数据；工作进程就绪消息另保存模型与适配器声明。

已同步记录可以帮助处理中断；强制终止无法执行清理代码，磁盘故障或断电也不承诺绝对零丢失。

相关代码在 `vla_runtime/records.py`。

### 5.2 Jetson联调入口

远程主机通过SSH别名配置，采用密钥登录和主机密钥检查。新入口不传密码、不自动运行sudo、不修改swap或电源模式。稳定测量前由管理员准备环境，脚本只检查前提。

视觉服务继续使用独立进程和5G/6G内存限制。新的运行目录由标签区分，不覆盖上次服务记录。服务启动失败、请求失败和资源结果均有文件输出；服务和采集进程在异常路径也会清理。

请求限制长度并检查图像尺寸，模型返回坐标统一走公共校验。输出记录提示词和图像摘要。设备电源模式不再在返回值中写死为15W，需由实际测量单独记录。

新源码包排除11个历史密码登录驱动。这些脚本仍可在仓库历史上下文中查阅，但不作为新交付的运行入口。新的可配置入口不等于已经替代全部旧性能分析工具。

相关代码在 `run_joint_service.py`、`remote_grounding_worker.py` 和 `vision_service.py`。

## 六、验证结果

### 6.1 离线回归

| 检查组 | 数量 | 结果 |
|---|---:|---|
| 原有策略、恢复、检查器与交付测试 | 92 | 全部通过 |
| 新增公共运行层与入口测试 | 35 | 全部通过 |
| 合计 | 127 | 全部通过 |

新增测试不仅检查正常输入，也实际启动小型子进程和本地Unix socket，验证分帧、超时、异常退出和停止处理。模拟器启动失败用一个立即退出的替身脚本触发，直接调用真实调度函数，检查返回码与落盘文件。

几何和规划接口测试使用合成输入，未冒充真实ROS消息录制回放；后续具备完整ROS环境时仍需补录制消息与完整仿真回归。

### 6.2 静态检查和交付验证

维护范围通过Ruff代码检查、格式检查；公共运行层9个Python模块通过mypy严格类型检查。检查范围保存在清单中，不以局部通过代替全仓声明。

源码包包含离线测试必需的数据和轨迹，不包含模型权重、PDF或视频。文件清单由共享校验模块生成。独立解压目录使用新的Python环境安装依赖并执行同一套检查；另用文件访问跟踪检查是否依赖原工作目录。

历史文件校验清单、逐组测试输出和静态检查输出放在本报告目录及交付的检查结果目录。运行时长和环境路径以这些实际输出为准。

相关代码在 `scripts/check_offline.py`、`scripts/check_engineering.py`、`scripts/build_review_bundle.py` 和 `tests/runtime/`。

## 七、使用和维护

先按 `docs/ENGINEERING_HARDENING.md` 安装运行层并填写本机配置，再做离线检查和只读诊断。需要完整模型、ROS2与仿真资产的命令在说明中单独列出，不能把“CPU检查通过”理解为这些依赖已经随包提供。

CPU依赖和开发工具有固定版本；模型与设备环境各自保留，不做跨平台混装。新增GitHub Actions配置可在仓库端执行同一套CPU检查，当前报告只引用本地实际运行结果。

本轮改进不改变已有研究结论：中文长任务的分层方案没有超过仅翻译对照，视觉检查器尚未显示稳定的任务成功率收益，端侧仍未达到既定实时目标。工程整理解决的是这些实验能否被更可靠地运行和检查，而非用代码整理替代算法突破。

## 八、后续验证边界

目前可以交付的是改进后的源码、配置、接口约束、离线验证和操作说明。下一次重新运行应使用新标签，重点检查：完整ROS2轨迹是否满足更严格的结构约束；新服务在实际Jetson环境的包安装与资源清理；完整操作与预接触收敛后是否保持既有行为。

历史脚本的全部路径、旧模型加载方式和报告生成脚本仍有逐步迁移空间。已维护入口和历史源码的范围写在清单与说明中，避免新旧实现混用。
