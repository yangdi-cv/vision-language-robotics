## 2. t9定位与单入口

固定t9初态0、相同动作噪声、512像素监测图、双票、夹爪门控及520步上限。初始规划使用已保存的英文子目标，消除初次Qwen生成文本变化，再分别替换执行逻辑、物体称呼和恢复设置。

| 配置 | 结果 | 步数 |
|---|---|---:|
| 历史逻辑＋原“yellow and white mug”计划 | 成功 | 257 |
| 严格逻辑＋同一原计划 | 成功 | 257 |
| 严格逻辑＋新“mug with yellow handle”计划 | 成功 | 267 |
| 严格逻辑＋新计划＋150步触发恢复 | 成功 | 267 |

前两组在相同原计划下的动作轨迹逐点一致。这次未稳定复现之前的超时，不能指定某个改动就是原因。旧失败回合与本次相同配置的初始图像逐像素一致，但第一步动作最大绝对差约0.000247，后续轨迹已经分开。四组结果及对比保存在`t9_results.json`、`t9_conclusion.json`；记录为未定位，不继续展开排查。

对外执行入口统一为`scripts/run_hierarchical.py`：

- `--execution-profile legacy|strict`选择历史或严格状态转换。
- `--planner-profile base|contract`选择原始或目标覆盖/终态约束规划。
- `--recovery-mode continue|full|replan`区分继续、整句重试和重规划。
- `--operation-checks`仍是默认关闭的实验选项。

Qwen worker统一由`qwen_planner.py --profile base|contract`启动。原recovery文件保留实现模块和兼容包装，共享图像、串口无关的进程通信等帮助函数，不再维护两套worker循环。历史算法实现保留用于复现；后续不增加平行启动入口。纯平坦执行也不再加载无用的Qwen worker。

## 3. 受控扰动实验

### 3.1 三类扰动

| 类型 | Long任务 | 注入方式 |
|---|---|---|
| 撤销一件入篮物体 | t0，汤罐和番茄酱入篮 | 第一个目标放置后，将汤罐恢复到原桌面姿态 |
| 破坏操作前提 | t3，碗入底层抽屉并关上 | 在放碗前关闭初始打开的底层抽屉 |
| 撤销一个杯子的放置 | t4，双杯分别放盘 | 白杯放置并释放后，将它恢复到原桌面姿态 |

每类使用公开初态0/1/2。对同一注入状态，比较继续原计划、整句英文重试、Qwen基于当前图像重规划。三分支的扰动状态哈希完全一致，动作噪声种子相同，各给420步恢复预算。t4部分源计划只有一个整句目标，此时“继续”保留真实的当前整句指令，没有为了制造差距而改成故意不完整的指令。

环境代码使用真值构造和检查扰动；策略和Qwen不读取这些值。恢复调用发生在约定的注入时刻，测试的是已通知扰动后的恢复能力，不是自动故障检测。新分支的恢复预算也不作为标准Long排行榜分数。

### 3.2 结果

| 扰动 | 继续原计划 | 整句重试 | Qwen重规划 |
|---|---:|---:|---:|
| t0，撤销入篮 | 0/3 | 2/3 | 0/3 |
| t3，关闭抽屉 | 0/3 | 0/3 | 0/3 |
| t4，撤销白杯 | 2/3 | 1/3 | 0/3 |
| 合计 | 2/9 | 3/9 | 0/9 |

![同一扰动状态下的恢复结果](figures/recovery_pair.png)

有控制策略救回的例子，说明本轮不全是不可执行状态；但抽屉类仍未被任一方法救回，不能把全部九个状态预设为可恢复。Qwen方案未超过整句重试，因此本轮恢复实验收尾，不继续扩大初态数。

保留的规划文本也暴露了两个具体问题：入篮任务可能添加未要求的开罐/开瓶动作；抽屉关闭后可能仍只给出放碗和关抽屉，没有补打开这个前提。它们不是JSON格式检查能解决的语义问题，本轮不再追加规划器分支。

协议在`injection_protocol.json`，逐例结果在`injection_results.json`，视频、状态和动作在`results/injection/`。

## 4. 完成检查器LoRA

### 4.1 数据与标签

从此前四个LIBERO任务集的120个基线回合提取720组图像对。第一张为回合初始图，第二张取早期、中段、终点前20步、终点前5步、终点前1步和终点。视频第k帧对应执行k步后的状态，标签读取`trace.predicate[k-1]`，不是Qwen生成答案。

按初态编号隔离：初态0训练、初态1验证、初态2测试，各40个完整回合、240例。回合和初态哈希没有交叉，完全相同的图像对及指令没有跨集合重叠。任务本身在三个集合中共享，这验证的是本次LoRA的初态留出效果，不是新任务泛化；公共初态也不等于基座预训练从未见过。

终点前5步和前1步共240例被单列为边界样例。其中训练侧80例不参加训练，验证侧80例不参加权重选择；测试侧80例仍完整报告，不隐藏难例。因此实际训练160例，权重选择使用验证集中的固定32正、32负共64例，最终测试240例分为常规160例和边界80例。后续阈值校准使用完整验证集240例，测试分数不用于选择阈值。

图像统一为两张256×256 RGB，与源视频分辨率一致；本轮没有深度输入。标签表示完整任务/目标条件全部满足。普通任务提供位置关系样例，Long任务提供多条件样例；未把最终判据随意映射给任意中间子目标。

### 4.2 训练配置与权重

基座为固定revision的`Qwen/Qwen3-VL-4B-Instruct`，BF16；视觉模块冻结，仅在语言层q/v投影上训练LoRA，rank8、alpha16、dropout0.05。可训练参数2,949,120，AdamW学习率5e-5，梯度累积2，正负均衡抽样，固定180次更新。

每60次更新在同一验证子集评估，以平衡准确率最高、再以误报率更低选择。第180步权重被选中，验证平衡准确率87.5%。测试集不选权重，没有做多轮超参数搜索。

权重在`results/checker_lora/best_adapter/`。训练、验证及微调后测试计时约103秒，不含之前的基座测试、数据提取、初次加载和后续校准。PyTorch记录的峰值分配约8.79GiB。独立新进程已重新载入保存的adapter，独立CLI输出与保存的测试概率一致。

### 4.3 独立测试：常规识别提升，边界误报严重

| 240例完整测试，贪心输出 | 基座 | LoRA |
|---|---:|---:|
| 总准确率 | 82.9% | 63.3% |
| 平衡准确率 | 51.6% | 72.9% |
| 已完成召回，39例 | 2/39（5.1%） | 34/39（87.2%） |
| 未完成误报，201例 | 4/201（2.0%） | 83/201（41.3%） |
| 输出格式合法 | 240/240 | 240/240 |

基座大多回答未完成，因负例较多而得到较高总准确率。LoRA能识别更多完成样本，但相应误报增加，不能只展示平衡准确率提升。

| 分层查看，贪心输出 | 基座 | LoRA |
|---|---:|---:|
| 常规160例准确率 | 76.9% | 86.3% |
| 常规负例误报率 | 0/121 | 17/121（14.0%） |
| 边界80例误报率 | 4/80（5.0%） | 66/80（82.5%） |

### 4.4 验证集阈值校准

另外按固定JSON前缀后true/false的相对概率做受限二分类。基座与LoRA使用同一方法，在验证集误报不超过5%的约束下选择召回最高的阈值。此项是追加的运行点校准，原始贪心结果全部保留。

| 校准后完整240例测试 | 基座 | LoRA |
|---|---:|---:|
| 完成召回 | 3/39（7.7%） | 5/39（12.8%） |
| 未完成误报 | 10/201（5.0%） | 14/201（7.0%） |
| 常规负例误报 | 2/121（1.7%） | 1/121（0.8%） |
| 边界80例误报 | 8/80（10.0%） | 13/80（16.3%） |

LoRA阈值为0.985936。验证集的5%约束没有保证测试集也满足，且低误报设置损失了大部分完成召回。因此这轮权重尚不适合用于自动阶段切换。数据正例主要是成功末帧，可能包含执行阶段和机械臂姿态的关联；下一轮应补充外观相似但失败的末帧及反事实负例，而不是立即接入机器人。

基座和LoRA使用同一份本轮提示词；这些数字不等同于旧分层系统原完成检查提示词的结果。仅含负例的边界子集不报告平衡准确率，避免给单类样本赋予误导性的数值。

## 5. 任务书对应与交付

本轮新增了可加载的Qwen-VL LoRA权重与独立推理脚本，是子任务1感知适配中的“完成检查”分支。任务书要求的RGB-D目标定位、可供性和子目标分解微调，不能据此算全部完成。导航、Jetson延迟及真机代测本轮未新增。代码、评测和报告则补充到可复现交付。

下一步只保留两项：整理与成功末帧相似的难负例并重新审核可观察标签；与导师确认完成检查分支及导航部分的验收范围。暂不扩大恢复回合或启动更多模型训练。

从工程根目录执行，环境沿用`.venvs/openpi-libero`与`.venvs/qwen-scene`：

```bash
# 同一入口选择严格状态与约束规划；只在仿真中运行
experiments/vla_libero/scripts/python_shared \
  experiments/vla_libero/scripts/run_hierarchical.py \
  --task-id 0 --init 0 --execution-profile strict \
  --planner-profile contract --planner qwen --monitor qwen \
  --subgoal-budget 150 --max-replans 1 --tag new_unique_tag

# 独立图像完成检查，输出结果，不控制机械臂
.venvs/qwen-scene/bin/python \
  experiments/vla_libero/closed_loop_iteration/scripts/check_completion.py \
  --before before.png --after now.png --instruction "put the mug on the plate" \
  --adapter experiments/vla_libero/closed_loop_iteration/results/checker_lora/best_adapter \
  --calibrated
```

数据生成代码在`prepare_checker_data.py`，训练在`train_checker.py`，验证校准在`calibrate_checker.py`，恢复实验在`run_injection.py`。首次输出拒绝覆盖，重跑请使用另存目录。源码包不含基座权重、环境和原始视频；LoRA权重单独打包，输入案例索引及标签随代码保留，图像可由已记录基线视频提取。
